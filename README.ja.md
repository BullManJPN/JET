# JET

**英語の音声を、Mac の中だけで日本語字幕にして、返答の準備も手伝う macOS アプリ。**

マイク、または Web 会議や動画のシステム音声で流れる英語を聞き取り、話してから約 **1.6 秒**で日本語字幕を表示します。「質問箱」は、英語で何か言いたいときの準備を手伝います。音声認識・翻訳・案の作成は、すべて Apple のオンデバイスの機能で Mac の中で行います。アプリは通信をせず、閉じると何も残りません(音声も書き起こしも保存しません)。

> 個人の非公式プロジェクトです。Apple をはじめ、文中に出てくる企業とは関係がなく、承認も受けていません。

## ねらい

クラウドの翻訳は、会議の音声をサーバーに送ります。JET は逆の条件で作りました。すべて端末の中で完結し、使ったあとには何も残らないことです。英語中心の Web 会議や英語の教材を見ながら、リアルタイムに内容を追い、次に何を言うかの手がかりを得るための道具です。

## 機能

- **流れる字幕。** 日本語を大きく、もとの英語を下に小さく出します。新しい行は下に積まれ、古い行は薄くなります。読んでいる行は書き換わりません。上へスクロールで読み返し、「↓ 最新へ」で戻ります。
- **質問箱。** 字幕の語をクリックで拾い、20 個の型(ビジネス/フランクの 2 つの口調)から選ぶと、Apple Foundation Models が英語の質問案を作ります。カナの読み・英語・日本語の 3 つを表示し、クリックで英語をコピーします。
- **画面共有に映らない。** 窓は画面共有に映らない設定(`sharingType = .none`)で、Web 会議の画面共有で確認済みです。
- **見た目の調整。** 背景の濃さ、明るい/暗い、フォント、文字の大きさを、窓の中の設定パネルで変えられます。
- **メニューバーのアプリ。** 開始・ポーズ・終了は窓の帯かメニューバーから。マイクとシステム音声の両方に対応します。

## プライバシーの設計

- アプリのソースに通信のコード(`URLSession` など)はありません。認識も翻訳も、Apple のオンデバイスの機能です。
- ビルドした `.app` には録音機能がなく、イベントも認識ログもファイルに書きません。字幕はメモリの中だけにあり、終了すると消えます。
- 消えてしまう内容(字幕、質問箱の入力、拾った語、生成中の案)があるときは、終了前に確認を出します。「保存して閉じる」は、設計として作っていません。
- 診断用のログ(`app.log`)には書き起こしの文字を入れません。開始・停止・エラーの種類だけです。
- 限界: macOS 自体のログやスワップはアプリでは制御できません。クリップボードは、あなたがクリックでコピーしたときだけ書きます。
- Terminal 運用(`./menubar.sh`、`jetcli`)は開発用です。イベントと認識ログを `logs/` に書き、`--save-audio` で録音もできます。
- 音声も文字も、どこにも送りません。ダウンロードが必要になる場合があるのは、英語の音声認識モデルが入っていないときだけです。そのときは macOS が 1 回ダウンロードします(JET 自体に通信のコードはありません)。

## 動作要件

- **Apple Intelligence に対応し、システム設定でオンにした** Mac(下書き訳と質問箱が Apple Foundation Models を使います)。Apple の対応機種は「M1 以降の Mac」で、Intel Mac は載っておらず、JET も試していません。端末の言語と Siri の言語が、Apple Intelligence の対応言語である必要があります。空き容量は Apple の案内で最大 8〜14 GB です。モデルは macOS がダウンロードします。準備ができていないときは、JET が「モデルが使えない」と表示するので、ダウンロードが終わるのを待ってください。
- 動作を確認したのは 1 台だけです。Mac mini(24 GB)・**macOS 27.2**・**Xcode 27.1**・**Swift 6.4**。`Info.plist` の対象は macOS 26.0 ですが、27.2 より古い環境では試していません。
- macOS SDK つきの `swiftc`(テスト環境は Xcode 27.1 / Swift 6.4。それより古い Xcode や Command Line Tools は試していません。使っている Foundation Models と SpeechAnalyzer は、macOS 26 以降の SDK が必要です)。アイコン作成に `sips` と `iconutil`(macOS 標準)を使います。

## ビルドと起動

ビルド済みのアプリは配布しません。各自でビルドしてください。

```sh
git clone <このリポジトリ> JET && cd JET
./build_app.sh
open JET.app
```

**署名。** `JET Local Signing` という名前の自己署名のコード署名証明書があれば、`build_app.sh` がそれで署名します。リビルドのたびに許可を聞き直されないためです。作り方: キーチェーンアクセス → 証明書アシスタント → 証明書を作成… → 名前 `JET Local Signing`、固有名のタイプ「自己署名ルート」、証明書のタイプ「コード署名」。証明書が無いときは ad hoc 署名になり、動きますが、ビルドのたびに許可を聞き直されることがあります。別の名前の証明書は `JET_SIGN_ID="名前" ./build_app.sh` で指定します。

**Terminal 運用**(開発用): `./menubar.sh` が `jetcli` をビルドし、selftest を通してからメニューバー版を起動します。テストだけなら `./jetcli --selftest` です。

## 必要な許可

| 許可 | 使い道 |
|---|---|
| マイク | マイクで聞き取る |
| 音声認識 | 英語のオンデバイス認識 |
| 画面収録とシステムオーディオ録音 | 会議や動画の音声の取り込み(ScreenCaptureKit) |

Terminal から起動すると、許可は JET ではなく Terminal に付きます。「画面収録とシステムオーディオ録音」を許可したあとは、Terminal を再起動してください。

## 使い方

1. アプリを開き、窓の帯の**開始**(またはメニューバー)を押します。入力は「マイク」か「システム音声」をメニューで選びます。
2. **ポーズ**は聞き取りだけを止め、字幕は残します。**×**は終了です(聞き取り中は 2 回押します)。
3. 窓は上端の帯か ⌘+ドラッグで動かし、辺や角でサイズを変えます。⌘+ / ⌘− で文字の大きさを変えます。
4. 帯の吹き出しアイコンにマウスを乗せると質問箱をのぞけます。クリックで左の列に固定します。
5. 字幕の語をクリックで拾い(Shift+クリックでつなげる)、型と口調を選び、言いたいことを入力して **Q** を押します。
6. 帯の右端の歯車で設定パネル(見た目・フォント・質問箱の型)を開きます。

### 発音辞書(カナの読み)

カナの読みは、同梱の CMU 発音辞書(`asr/cmudict.dict`。[THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md))と規則で作ります。ファイルが無いときは、読みを出さず、その旨を表示します。戻すには次を実行します。

```sh
curl -L -o asr/cmudict.dict https://raw.githubusercontent.com/cmusphinx/cmudict/master/cmudict.dict
```

## 設定

- `jet.json` が既定値です。`.app` では、変えた項目だけが `~/Library/Application Support/JET/jet.json` に保存され、同梱の既定値の上に重ねて読まれます。
- 質問箱の型: `prompts/qbox_templates.tsv`(設定パネルから編集。編集版は Application Support に置かれます)。
- 認識結果の用語補正: `asr/terms.txt` と `asr/term_aliases.tsv`。自分で足した行は、同梱の行より先に合算されます。

## 仕組み

```
音声 ─▶ SpeechAnalyzer(途中経過のテキスト) ─▶ LocalAgreement(2回連続で一致した語を確定)
     ─▶ 節の判定 ─▶ Apple Foundation Models(下書き訳。文脈なし・greedy) ─▶ 流れる字幕
```

測定から決めたこと(詳しい数字は [research/FINDINGS.md](research/FINDINGS.md)):

- **例文(few-shot)を使わない。** オンデバイスのモデルは、例文を「お手本」ではなく「写す材料」として扱いました。例文を 8 件にすると、例文の漏れが 212 件、誤訳が 39% に増えました。例文なしでは、読める訳が 93.2%(認識された英語がまともな節で)、漏れは 0 でした。
- **語単位で確定する。** 認識器の最終結果を待つと中央値 3.4 秒、2 回連続で一致した語を確定すると 1.3 秒でした。
- **辞書にない語は最長 3 秒待つ。** 崩れた語を含む節が 16.5% から 8.2% に減り、中央値の遅れは変わりませんでした。
- **下書きだけにする。** 字幕は書き換えません。クラウドの「最終訳」は作って測定したうえで、すべてローカルで動かすために削除しました。

## 測定した動作

テスト機で、英語は話してから約 1.3〜1.4 秒、日本語の下書きは節が閉じてから 0.26〜0.32 秒(合計で約 1.6 秒)に出ます。数字は Mac mini 1 台と少数の公開動画によるもので、ベンチマークではなく目安です。

## 限界

- 下書き訳の質は、オンデバイスのモデルの質です。認識の間違いは聞こえたとおりに訳されます。否定・比較・数で意味が逆になる訳も、少数あります。字幕は内容を追う補助であり、書き起こしや正式な翻訳ではありません。
- モデルが安全機構で止まったり、中国語の文字が混ざったりすることがあります。そのときは、英語をそのまま表示します。
- 英語から日本語のみ。動作確認は 1 台のみ。質問箱は発言の準備用で、即答用ではありません。

## リポジトリの構成

| パス | 内容 |
|---|---|
| `jet/` | アプリの Swift ソース |
| `app/` | `Info.plist`、アイコン |
| `prompts/`、`asr/` | プロンプトと質問箱の型、用語集・発音辞書・単語表 |

`research/` には、翻訳の採点に Anthropic の API を使うスクリプトがあります。自分の API キーが必要で、アプリの動作とは無関係です。
